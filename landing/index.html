Time tracking

Attendance, without the surveillance.

Clock in/out with breaks, manual hour entries, and pay-period lifecycles your team can drive from the API — or an agent.

Clock in/out & breaks

Punches, breaks, and manual hour entries — all idempotent, so a retried request never double-counts time.

Pay-period lifecycle

Open → Submitted → Approved / Rejected → Reopened, with recalculation and a full audit of every transition.

Shift scheduling

First-class shift scheduling — rosters as a core concept, not an afterthought.

Overtime engine

Configurable overtime rules that feed directly into payroll lines.

Deliberately absent: face recognition, GPS tracking, and screenshots. Time tracking shouldn’t require surveillance.

Leave

Time off with real accrual math.

Policies that accrue, carry forward, and expire — requests with frozen snapshots, ordered approval chains, and a live balance ledger.

Accrual policies

Annual, monthly, or pay-period accrual with carry-forward rules and expiry — computed, not guessed.

Approval chains

Ordered multi-step approvals with a live balance check, so a request can’t outspend what’s accrued.

Live balances

A balance ledger per employee and policy — every accrual, request, and approval leaves a trace.

Holiday calendars

Public-holiday calendars per country and region, wired into request validation and reporting.

Leave is tracked in whole working days — half-day leave isn’t modeled yet.

Payroll

Statutory payroll for Malaysia and Indonesia.

Draft → Approved → Locked runs, payroll-item presets with per-item statutory flags, and versioned rule packs for MY and ID statutory requirements.

Run lifecycle

Draft → Approved → Locked. Locking a run freezes it against further changes — with full audit history.

Item presets

A catalog of payroll-item presets, each with statutory flags declaring how it interacts with contributions and tax.

MY rule pack

EPF, SOCSO, EIS, PCB, and HRDF calculations derived from worker status and age band.

ID rule pack

BPJS Kesehatan and BPJS Ketenagakerjaan (JHT/JKK/JKM/JP), plus PPh 21 tax calculations.

Payslips & bank files

Payslip generation per employee and bank-file exports (Maybank first) — files for your bank portal, not bank API debits.

Statutory exports

MY: EPF CSV, PCB text files, Borang A. ID: BPJS and PPh 21 report formats.

Agent-ready

Agents are operators here, not integrations.

The agent surface is generated from the same handlers as the REST API — same store, same auth model, same audit trail. Nothing is bolted on.

MCP server

37 hris.* tools over stdio or HTTP — time, leave, payroll, and reporting, with the OpenAPI 3.1 contract as the source of truth.

Approval gates

Sensitive tools don’t just run: creates, approvals, and money operations return an approval request with a resume token instead of executing.

Preview → submit

Irreversible operations are two-phase. Payroll submission requires a live preview payload — no blind money movement.

Signed webhooks

HMAC-SHA256 signed, at-least-once event delivery so agents and systems can react to every state change.

SCIM 2.0

Provision and deprovision users and groups from your identity provider with standard SCIM endpoints.

Audit & idempotency

Append-only, hash-chained audit log with agent identity on every entry — and Idempotency-Key on all POSTs.

How it works

Running in three steps.

1

Start everything

One command brings up Postgres 16, the REST API on :8080, and the MCP server on :8081.

git clone https://github.com/azmi2409/forge-hris
cd forge-hris
docker compose up -d

2

Create your org & invite the team

Bootstrap the first organization via the API — the owner token is shown once. Then issue personal access tokens and invite your team with role-based access.

3

Connect your agent via MCP

Point any MCP-capable client at the server over stdio or HTTP. Example — adapt to your client:

{
  "mcpServers": {
    "forge-hris": {
      "command": "forge-hris-mcp",
      "args": ["--stdio"],
      "env": { "FORGE_HRIS_MCP_TOKEN": "<your-PAT>" }
    }
  }
}

Good to know

  • Statutory rule packs are versioned — but they must be re-verified against official LHDN, EPF, SOCSO, BPJS, and tax-authority sources before any real payroll run.
  • This is self-hosted software. You run it, you operate it, and your data stays yours.
  • No face recognition, GPS tracking, or screenshots — by design. Leave is tracked in whole working days.
